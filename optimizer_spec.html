Transfer Optimizer — Mathematical Specification

Written before implementation. Every open parameter below was a genuine decision, not an assumption.

Notation

SymbolMeaning
$S$Current 15-man squad, partitioned by position: $S_{GKP}, S_{DEF}, S_{MID}, S_{FWD}$
$C$Candidate pool — all eligible players not currently owned
$T$Target number of transfers (given)
$F$Free transfers available this week
$O \subseteq S$Chosen outgoing (sold) players, $|O| = T$
$I \subseteq C$Chosen incoming (bought) players, $|I| = T$
$p_j$Projected points for player $j$, multi-gameweek horizon (next 4 GWs)
$v_j$Player $j$'s price, £m
$\text{sp}_i$Real selling price of owned player $i$ (from authenticated my-team data)

Objective function

Maximize the aggregate points-per-value of the incoming set only. Selling choices do not appear in the objective directly — they matter only for feasibility, addressed in the constraints below.

$$ \max_{I} \; R(I) \;=\; \dfrac{\displaystyle\sum_{j \in I} p_j}{\displaystyle\sum_{j \in I} v_j \;+\; \Delta V_{hit}} $$
Decision: aggregate formulation chosen over the alternative (mean of each incoming player's own $p_j/v_j$ ratio) — total points bought per total £m spent, not average individual efficiency.

Hit-cost mechanism

Transfers beyond the free allowance cost $-4$ points each under FPL's own rules. Rather than subtracting this from the numerator, it is converted into an equivalent value inflation added to the denominator — expressed in the same units the objective already uses:

$$ \Delta V_{hit} \;=\; \dfrac{4 \cdot \max(0,\, T - F)}{\lambda} \qquad\qquad \lambda \;=\; \dfrac{1}{|C|}\sum_{k \in C} \dfrac{p_k}{v_k} $$

$\lambda$ is the market rate — mean points-per-£m across the entire candidate pool right now — used to translate a raw points penalty into a comparable £m quantity.

Decision: $\lambda$ computed from the live candidate pool (market-rate), not a fixed constant.
Note: because the objective is aggregate, $\Delta V_{hit}$ only needs to be added once to the total denominator — no need to decide which specific incoming player "absorbs" the penalty.

Constraints

  1. Squad composition — the resulting 15-man squad has exactly 2 GKP, 5 DEF, 5 MID, 3 FWD: $$ |O \cap S_{pos}| = |I \cap C_{pos}| \quad \text{for each position } pos $$
  2. Budget — using real selling price, not current price, since FPL's 50% profit-sell rule means they can differ: $$ \text{bank} + \sum_{i \in O} \text{sp}_i \;\geq\; \sum_{j \in I} v_j $$
  3. Club limit — no more than 3 players from any one real-world club in the resulting squad: $$ \text{count}_{club}(S \setminus O \cup I) \leq 3 \quad \text{for every club} $$
  4. Eligibility — $O \subseteq S$, $I \subseteq C$, $O \cap I = \emptyset$.
Stated limitation: accurate $\text{sp}_i$ (real selling price) is only available via authenticated login. Rather than approximate it from current price when not logged in — which would be silently wrong whenever a player's risen in value — the optimizer refuses to run at all without login.

Solution method

The search is two-stage, following directly from the fact that $O$ doesn't appear in the objective:

  1. Stage 1 — find the best $I$: search combinations of buy candidates per position, ranked by $R(I)$. A full search of every real candidate ($|C| \approx 500+$) is combinatorially infeasible, so this stage is bounded to a shortlist of the strongest ~15 candidates per position by projected points.
  2. Stage 2 — find a feasible $O$ for that $I$: full, unbounded search across your actual squad (small — at most 5 players per position) for any combination satisfying the budget and club-limit constraints. Among feasible options, the one forfeiting the fewest points is chosen as a tie-break. If no feasible $O$ exists, move to the next-best $I$ from Stage 1 and repeat.
Decision: sell-side search is exhaustive (no bound), per explicit instruction — only the buy-side shortlist is bounded, and only because exhaustive search there is not computationally tractable, not by preference.
