Workflow

The agentic loop, end to end

This replaces today's single Claude call with a closed loop: research is iterative, the draft checks itself against hard constraints before you ever see it, and the outcome feeds back in so next week's version of this loop is informed by whether last week's call was actually right.

1 · Gather
live stats + last week's logged outcome
↓
2 · Research
iterative search, cites sources, follows up on gaps
↓
3 · Draft
recommendation, in structured form
↓
4 · Self-critique
checks budget, free transfers, chips used
fails → back to Draft
↓ passes
5 · Present + confidence
optional: execute via your logged-in session
↓
6 · Store outcome
resolved the following week, once results are in
↑ feeds back into next week's Gather step

Module specs

Seven components, each independently gated

M1 · Memory store Designed

JSON file in your GitHub repo, read/written via GitHub's Contents API. One record per gameweek: the recommendation made, and the outcome filled in a week later once results are known.

Interfaceget_recent(n), append_decision(record), resolve_outcome(gw, outcome)
New secretsGITHUB_TOKEN, GITHUB_REPO
Depends onNothing — foundational
M2 · Structured output schema Proposed

Right now Claude returns free-text prose. Every downstream module (confidence bars, the decision log, action-taking) needs a machine-readable shape instead — the same content, structured.

Shape{transfer, chip, captain, confidence: {transfer, chip, captain}, sources: [...], rationale: str}
MechanismClaude's tool-use / forced JSON output, not prompt-and-hope parsing
Carries forwardrival_mode (season-long vs head-to-head) and the trend-based aggression lean (favor differential/aggressive picks when the gap to your chosen rival is widening) — both already live today, explicitly preserved as required inputs to this schema, not dropped in the rebuild.
Depends onM1 (the schema needs to match what memory stores)
M3 · Iterative research Proposed

Multiple search rounds instead of one: if the first search on an injury is ambiguous, the model searches again rather than guessing.

MechanismClaude API's native multi-turn tool loop (several round trips server-side before you see output)
Cost impactHigher than today's single call — 2-4x more tokens typically
Depends onM2
M4 · Self-critique Proposed

A second pass that checks the draft against hard rules (free transfer count, chips already used, bank) before you see it — catching the exact "use both" bug we hit earlier, automatically, every time.

MechanismDeterministic Python validation of the structured output, not another LLM call
On failureRe-prompts Claude once with the specific violation named, then surfaces to you if still wrong
Depends onM2, M3
M5 · Confidence signaling Proposed

Each of the three calls (transfer, chip, captain) gets its own confidence level, shown as a bar rather than buried in prose tone.

Depends onM2 (needs the structured field to exist)
M6 · Decision log UI Proposed

Replaces the current "button → wall of text" page with the scrollable card feed mocked up below, PLUS a current-vs-proposed squad diff so a transfer, captaincy change, or chip call is visible at a glance rather than read out in prose.

Depends onM1, M2, M5, plus reuses app.py's existing team-sheet row rendering rather than duplicating it
M7 · Action-taking Gated — separate sign-off required

Actually executes the transfer via your authenticated FPL session, on your explicit tap — not automatic, not silent. This is the only module that takes an irreversible real-world action, so it gets its own dedicated review after M1–M6 have a track record, not bundled in now.

Depends onEverything else, plus a proven track record from the memory store
