Transfer Optimizer — Solver Reformulation

Addendum to the original specification. Replaces the bounded heuristic search with an exact MILP solve.

Why this is needed

The original spec's objective, $R(I) = \sum p_j / (\sum v_j + \Delta V_{hit})$, is a ratio. CBC — like virtually every MILP solver — only optimizes linear objectives directly. The original implementation worked around this with a hand-bounded search (top-15 candidates per position). This reformulation removes that bound entirely via an exact technique: Dinkelbach's algorithm.

Decision variables (unchanged in meaning, now solver-native)

VariableMeaning
$x_j \in \{0,1\}$, for $j \in C$1 if candidate $j$ is bought
$y_i \in \{0,1\}$, for $i \in S$1 if owned player $i$ is sold
Improvement over v1: position allocation no longer needs to be enumerated by hand (the "partitions" step in the original two-stage search). The solver decides the optimal split across positions itself, subject to the constraint below — this was a manual step before and is now automatic.

Constraints, restated for the solver

$$ \sum_{j \in C_{pos}} x_j = \sum_{i \in S_{pos}} y_i \quad \text{for each position } pos \qquad \text{(composition preserved)} $$ $$ \sum_{j \in C} x_j = T, \qquad \sum_{i \in S} y_i = T $$ $$ \text{bank} + \sum_{i \in S} y_i \cdot \text{sp}_i \;\geq\; \sum_{j \in C} x_j \cdot v_j \qquad \text{(budget)} $$ $$ \text{count}_{club}(S) - \sum_{i \in S_{club}} y_i + \sum_{j \in C_{club}} x_j \;\leq\; 3 \quad \text{for every club} \qquad \text{(club limit)} $$

Dinkelbach's algorithm

Instead of maximizing the ratio directly, solve a sequence of ordinary linear problems, each parametrized by a trial ratio $q$:

$$ F(q) \;=\; \max_{x,y} \; \sum_{j \in C} x_j p_j \;-\; q \sum_{j \in C} x_j v_j \quad \text{subject to all constraints above} $$

Note $\Delta V_{hit}$ is a known constant once $T$ and $F$ (free transfers) are fixed — it doesn't depend on which players are chosen, so it drops out of the arg-max and is only added back when computing the actual ratio for the convergence check below.

  1. Initialize $q_0 = 0$.
  2. Solve the linear problem $F(q_n)$ with CBC — a single, ordinary MILP solve, no ratio involved.
  3. Extract the optimal $x^*, y^*$ found, compute the actual ratio at that solution: $$ q_{n+1} \;=\; \dfrac{\sum_j x_j^* p_j}{\sum_j x_j^* v_j + \Delta V_{hit}} $$
  4. Check convergence: if $|q_{n+1} - q_n| < \varepsilon$ (e.g. $10^{-6}$), stop — $x^*, y^*$ is the exact optimum. Otherwise set $q_n \leftarrow q_{n+1}$ and repeat from step 2.

This is a standard, exact method for fractional 0-1 programming (Dinkelbach, 1967) — not a heuristic approximation. It typically converges in 5-10 iterations for problems this size, meaning 5-10 fast CBC solves rather than one intractable combinatorial search.

Solver

PuLP + CBC — both free, open-source, no license or account required. CBC ships bundled with PuLP, so no separate installation step. This is the same stack used by most existing open-source FPL optimizer projects.

Net effect: the buy-side shortlist-of-15 limitation from the original spec is eliminated. CBC searches the entire real candidate pool (~500+ players) exactly, and the two-stage manual search (best $I$, then feasible $O$) becomes one joint solve per Dinkelbach iteration.
